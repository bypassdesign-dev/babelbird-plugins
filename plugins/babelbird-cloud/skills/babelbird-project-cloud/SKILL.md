# 巴别鸟工程云存储

将用户指定的工程保存到巴别鸟目录，或下载工程继续工作。使用宿主智能体的文件工具处理本地工程，使用巴别鸟 MCP 定位目录并申请传输地址。Skill 本身不提供账号授权、后台同步服务或云端代码运行环境。

## 首次使用：填写 API Key

首次使用必须先要求用户填写自己的巴别鸟 API Key，再进行需要认证的连接测试和文件操作。提示：

> 首次使用需要配置你的巴别鸟 API Key。请到巴别鸟“设置 > API秘钥”打开对应应用，复制上方的“APIKey”，并在当前智能体的私密凭据入口填写。这里需要的是 APIKey，不是 APP Key 或 APP Secret。

读取 [首次配置流程](references/setup.md#首次配置流程)，使用宿主支持的凭据入口或本机私有凭据存储。用户已在当前私密会话中主动提供 API Key，视为已填写，不重复索要。没有已填写或已登记的凭据时，等待用户填写，不使用演示密钥、共享密钥或猜测的凭据。

首次配置后记录不含密钥的连接信息及凭据引用，后续直接复用。将“凭据已保存”和“连接验证通过”分开记录；超时或断连不等于密钥失效，不要求用户反复填写。只有明确的凭据无效或用户更换账号／密钥时，才进入重新填写流程。

## 连接与能力

首次使用或连接失效时，读取 [连接与安装](references/setup.md)。使用当前会话发现的工具名称和参数；调用前读取 [MCP 接口与上传条件](references/mcp-tools.md)。

先执行 `getUsageAndQuota` 等只读检查。检查失败时保留本地工作，报告“云端未验证”，恢复连接后再继续。不得根据安装完成或工具列表可见推断连接成功。

确认宿主能读取待保存的本地文件、发送文件字节并写入下载结果。远程 MCP 不能通过用户电脑上的绝对路径直接读取该电脑的文件。

## 选择操作

| 用户意图 | 操作 |
| --- | --- |
| 保存整个工程、备份项目、换电脑继续 | 创建独立工程快照，按下述流程上传 |
| 保存某几个文件或生成的成果 | 上传明确指定的文件，保留需要的相对目录 |
| 从巴别鸟恢复工程 | 下载选定快照，校验后解压到新目录 |
| 每次完成后保存 | 在用户已授权的范围内于任务结束时执行保存；跨会话或无人值守运行需要宿主自动化能力 |
| 双向同步、镜像删除、多人实时编辑 | 解释本 Skill 的能力边界，不能将快照流程称为这些功能 |

用户已经明确的工程根目录、云端目录和保存范围可直接使用。缺少工程或目标目录时，只补问缺失项；不自行把当前会话所有文件上传到网盘根目录。

## 保存

1. 定位用户指定的本地工程根目录及云端目标目录。云端路径通过 `getFileInfoByPath` 或逐级分页列表解析为真实目录 ID。缺失目录通过已验证的父目录逐级创建；始终显式传入目标 ID。
2. 若当前部署提供工作目录工具，调用实际提供的工具选择目录；否则在本地记录目录绑定，每次写入显式携带目录 ID。遵守服务端权限检查。
3. 读取 [工程快照与恢复](references/project-storage.md)，确定纳入文件和排除项，报告计划保存的位置、数量和大小。用户的保存请求已授权相应范围内的新快照，无须重复索要同一授权。
4. 使用唯一名称创建快照，例如 `网站改版-20261020T143000+0800-a7f3.zip`。名称中的时间和随机标识须在执行时生成。包内包含工程文件、清单和恢复说明。
5. 检查配额、单文件限制与本地快照完整性。若配额字段含义或服务端限制不明，报告无法预检的部分，不能声称检查通过。
6. 按已确认的服务端协议计算上传所需的 `fileHash`，调用 `getUploadUrl`，再发送实际文件字节。完整规则见 [上传条件](references/mcp-tools.md#上传必须满足的条件)。
7. 检查传输响应中的 HTTP 与业务状态，再通过文件 ID 或精确路径核对云端文件名、大小和目标目录。下载回读并比较 SHA-256 才能报告“内容校验通过”；只有元数据时报告“上传完成，内容未回读校验”。
8. 输出云端目录、文件名、真实文件 ID、已完成的验证、排除项和恢复方法。仅使用服务端返回的稳定链接，不编造网盘文件 URL，不输出临时签名上传／下载 URL。

更新已有文件时，必须有覆盖或更新该文件的用户授权并使用已核实的 `fileId`。普通“保存工程”默认新增快照；不得根据旧文件名自动覆盖。网络超时后先核对是否已创建，无法确定时报告结果未知，避免重复写入。

## 恢复

1. 在用户指定目录中分页查找快照，使用真实文件 ID。存在多个候选且无法从请求确定版本时请用户选择。
2. 使用 `getDownloadUrl` 下载原始字节。`getFileContent` 可能返回提取文本，不能用于恢复 ZIP 或任意二进制文件。
3. 将文件下载到独立临时目录，核对来源、大小及可获取的校验值。快照内清单只用于检测内容一致性，不是独立的来源认证。
4. 校验归档成员路径、文件类型和展开大小，拒绝路径越界及危险链接，按 [恢复规则](references/project-storage.md#恢复规则) 解压到新目录。
5. 核对清单中的每个文件。说明哪些依赖和本地配置需要重新准备；只有实际执行并通过启动检查，才能声称工程可运行。

## 完成状态

最终答复明确区分：本地已打包、云端已上传、云端元数据已核对、内容已回读校验、工程已恢复、运行已验证。连接失败、协议缺失或部分文件失败时列出具体阻塞和已保留的本地结果，不报告整体保存成功。
