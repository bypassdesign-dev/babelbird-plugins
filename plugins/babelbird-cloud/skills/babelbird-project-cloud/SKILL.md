# 项目云端同步巴别鸟插件 / BabelBird Project Cloud Sync

将用户指定的工程按原目录结构逐文件保存到巴别鸟，或下载到本地继续工作。工程不压缩成 ZIP，不改写源码和原文件名；宿主负责读写本地文件和传输字节，MCP 负责定位云端目录并申请传输地址。

用户允许将工程自身的配置（例如 .mcp.json）保存在其指定的私有云端工程中。遵循脚本的排除清单和 Git 忽略规则；不要把宿主全局凭据或本插件的 API Key 复制进工程。使用用户当前语言引导与报告。

## 首次使用：填写 API Key

Meta Muse 个人智能体 / today.ai 使用 `muse` / `today` 实验分支，先读 `babelbird-setup` 的 [平台原生连接](../babelbird-setup/references/personal-agents.md)。密钥交由平台原生安全界面管理；不向用户发送云端 VM 的本地设置页地址。仅同步当前平台实际可访问的工作区，平台云端文件不等于用户电脑文件；两款产品的完整实机连接尚待验证。

其余六款宿主首次使用先检查当前已加载的巴别鸟 MCP；有效时复用并只读验证，不重复要求填写。缺少凭据时主动执行 `babelbird-setup`，按实际宿主 ID（`codex`、`workbuddy`、`codebuddy`、`claude`、`cursor`、`gemini`）打开同机中英文单密码框页面，分享返回的 URL，并以 `--host <id> --wait` 自动等待结果，每次最多 25 秒，不要求额外回复“已填写”。页面检查成功和宿主已加载 MCP 分别验证；WorkBuddy 第三方 MCP 权限由用户在应用内批准。

读取 [首次配置流程](references/setup.md#首次配置流程) 和 [API Key 填写入口](references/credential-entry.md)。需要获取 Key 时使用 [官方教程](https://www.babel.cc/public/babelwiki/zh/mcp-integration.html) 与 [获取步骤](references/api-key.md)：需要应用详情里的 APIKey，不是 APP Key 或 APP Secret。普通超时不代表密钥失效；仅明确无效或更换账号／密钥时重新填写。手工配置只作本地页不可用的备用方案，真实密钥不得进入聊天、工程或分发包。

## 连接与能力

使用当前实际发现的工具名称与 schema；调用前读取 [MCP 接口与上传条件](references/mcp-tools.md)。默认通过 `getFileInfoByPath` 定位 `/个人文件`，再用返回的目录 ID 调用 `listFolder`（页号 0、每页 1 条）检查连接；用户已指定其他目录时检查该目录。MCP 和业务状态都成功（包括空目录）才算只读检查通过，不能只看 HTTP 200 或工具列表。

默认跳过 `getUsageAndQuota`。仅在用户明确查询空间时调用；该查询超时、`Transport closed` 或流结束但没有业务结果时，记录“配额未知，已跳过查询”，不重试、不阻塞已授权的存储流程、不重新索要密钥。此例外不适用于鉴权失败、目录读取失败、明确空间不足或真实上传／下载错误。

确认宿主能读取工程文件、发送原始字节并写入下载结果；远程 MCP 不能通过用户电脑的绝对路径读取文件。

## 自动同步与跨设备续接

按 [同步执行流程](references/sync.md) 使用随包的 Node.js 20+ 脚本建立绑定、扫描文件、计算增量、传输字节与记录基线。MCP 调用使用宿主已有连接，脚本不读取 API Key；临时传输凭据只经标准输入传入，不落到工程。

首次配置后，用户要求启用工程同步且当前工程明确时建立绑定；后续在每次任务编辑前拉取云端更新、每批修改完成后自动上传本地变更，任务结束前复查，无须每次再说“保存”。绑定会保存本地目标引用并追加项目规则，保留已有规则。没有确定工程时只完成连接配置；明确只读测试时不创建目录、不绑定、不上传。

已存在 `.babelbird-sync.json` 时始终复用它的云端目录，不因换设备、换模型或换宿主改为新的默认位置。用户可指定任意有权访问的既有工程目录并下载到新本地目录；例如 WorkBuddy 继续使用 `/个人文件/codex/网站改版/`。绑定不同目录前先处理旧绑定及待同步改动，不静默重绑。

基于共同基线判定：只有本地变化则上传，只有云端变化则下载，两边都变且不同则报告冲突并保留双方，不自动覆盖。没有共同基线的同名文件先下载到内存核对内容；不按修改时间选择胜者。删除不自动传播。断网保留本地修改与原基线，恢复后重新比较；不同步不等于任务文件丢失。

这是智能体任务期间的自动同步，不是关闭应用后常驻监听的网盘客户端，也不是将云端目录挂载成本地磁盘。新会话依赖宿主加载项目规则；首次绑定后建议重新打开项目会话。

## 默认目录

| 实际运行宿主 | 默认工程目录 |
| --- | --- |
| Codex | `/个人文件/codex/<工程名>/` |
| WorkBuddy | `/个人文件/workbuddy/<工程名>/` |
| CodeBuddy CLI | `/个人文件/codebuddy/<工程名>/` |
| Claude Code | `/个人文件/claude/<工程名>/` |
| Cursor | `/个人文件/cursor/<工程名>/` |
| Gemini CLI | `/个人文件/gemini/<工程名>/` |
| Meta Muse 个人智能体（实验） | `/个人文件/muse/<工程名>/` |
| today.ai（实验） | `/个人文件/today/<工程名>/` |

按实际应用识别宿主，不按模型名、工程内容或对话中提到的产品名判断。用户明确指定的云端目录优先，直接作为工程根目录，不再追加宿主或工程名。其他宿主或宿主无法确定时，询问目标目录，不猜测分区。

工程名默认取已确定的本地工程根目录名。当前工程和宿主都明确时直接使用默认位置，不再追问云端目录。用户明确的保存范围优先；无法确定本地工程时只补问工程位置。工程内文件保持原名和相对路径，不给每个文件添加 codex 或 workbuddy 前缀。

通过 `getFileInfoByPath` 和分页列表核对个人文件、宿主目录与工程目录的真实 ID。不可将协议根目录 ID `0` 当作个人文件，也不可跨账号硬编码目录 ID。仅在用户已请求保存或启用工程同步时，按已核实的父目录逐级创建缺失的宿主目录、工程目录和子目录。读取或权限失败不能当成“目录不存在”；无权访问默认位置时说明具体限制，不自行改存企业文件、应用专用目录或其他账号。

## 保存

1. 确定工程根目录、保存范围及默认或用户指定的云端工程目录。读取 [逐文件存储与恢复](references/project-storage.md)，排除密钥、缓存与不支持的文件类型，列出计划保存的位置、文件数与总大小。保存请求已授权相应范围内的新建目录和新增文件，无须重复确认。
2. 在本地生成待上传清单，记录相对路径、字节数与 SHA-256。清单和回执按同步执行流程保存在本地并排除上传；不生成 ZIP，不额外上传辅助清单。先确认上传协议和本地传输能力，再创建云端目录。公有云协议已验证；其他部署响应与已验证协议不同时保留本地工程与清单，报告具体缺失项。
3. 按相对路径映射云端目录，为每个文件显式提供已核实的父目录 ID。当前部署有工作目录工具时可使用实际提供的工具；没有时记录绑定并逐次传 ID，不编造工具。
4. 每个普通文件使用原文件名，按当前接口说明计算 `fileHash`（当前公有云为文件 MD5），调用 `getUploadUrl` 后传输实际字节。实际上传方法和字段须满足 [上传条件](references/mcp-tools.md#上传必须满足的条件)。剩余配额未知只注明“未预检”；明确空间不足或超限必须处理。
5. 核对每个文件的传输 HTTP 与业务状态，以及云端文件名、大小、父目录和真实文件 ID。回读原始字节并比较 SHA-256 后才标记“内容已校验”；只核对元数据则注明“内容未回读校验”。
6. 逐文件更新本地回执并汇总成功、失败、结果未知、跳过项。部分失败不声称整个工程已保存；重试只处理未完成项。超时或断连后先查目标文件，结果不明时不盲目重传。

同名工程目录已存在时核对位置后复用。新增文件可继续；已有同名文件只有经内容校验一致才可标为跳过，不能仅凭大小和名称判定一致。已启用自动同步的绑定允许按共同基线更新没有冲突的文件，无须逐文件重复询问；不在该范围或出现冲突时先询问。更新前再次核对远端版本并使用真实 `fileId`。不自动删除云端多出的文件，不把该流程称为双向同步或镜像。

## 恢复

1. 按用户提供的云端目录或本地回执选择工程；默认可在当前宿主分区查找。多个候选无法确定时询问。递归、分页枚举整个工程目录，记录真实文件 ID 和相对路径，不只读取首页。
2. 按 [恢复规则](references/project-storage.md#恢复规则) 检查路径和文件类型，下载到新建的空本地目录；为每个文件调用 `getDownloadUrl` 获取原始字节，保留原文件名与相对路径。`getFileContent` 的提取文本不能替代原文件。
3. 对照目录清单核对文件是否齐全、大小是否一致。有可信的本地上传回执或服务端校验值时再核对内容；没有预期 SHA-256 时，单独计算下载文件哈希不能证明其与上传时相同。
4. 输出恢复路径、完成与失败项，以及需要重新准备的依赖或私有配置。只有实际执行并通过启动检查，才能声称工程可运行。

## 完成状态

区分本地清单已准备、云端目录已准备、文件已上传、元数据已核对、内容已回读校验、工程已恢复和运行已验证。未完成上传时不能用“连接通过”代替保存成功。只展示服务端提供的稳定链接，不输出 API Key 或临时签名 URL。插件不会在智能体关闭后继续同步，也不提供云端代码运行。
